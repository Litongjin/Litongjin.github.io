## 🚀 技能提升点（工作总结汇总）

### 1. Quill 工具栏配置数组展平
- **技能点**：构建框架所需配置时，遇到「一个配置名产出多个控件」必须将映射结果扁平化，保证每个控件是独立对象。
- **坑点**：getDefaultButtonConfig 的 list/indent 返回数组，调用方用 map 未展平，Quill 把数组当对象，Object.keys()[0] 为 '0'，生成了 ql-0 空按钮。
- **解决方案**：order.map 改为 order.flatMap，数组项展开为独立 control；lint 通过、按钮恢复正常。
```text
return order.flatMap((name) => getDefaultButtonConfig(name) ?? name)
```
- **拓展**：任何第三方库的配置映射，均需确认消费端是否支持嵌套数组。
- *来源：admin-workspace-new / 2026-08-12*

### 2. Vue watch 双向同步守卫
- **技能点**：多状态双向同步时，每一步写回前都做值比较，防止无实际变化的赋值反复唤起对端 watch。
- **坑点**：标志→sizes 数组→标志的同步链中，每次写新数组引用（即使值相同）都触发 deep watch，双方互相唤醒直至 Maximum recursive updates。
- **解决方案**：syncSizesFromFlags 计算 next 后逐项比对，相等直接 return；回写标志前先判断当前值 !== 推导值再写。
```text
const next = [left, 'auto', right];
if (next.every((v, i) => v === localPanelSizes.value[i])) return;
localPanelSizes.value = next;
```
- **拓展**：更深层做法是消除双向同步，改为单一数据源派生所有状态。
- *来源：admin-workspace / 2026-08-11*

### 3. UI 排查先验 DOM
- **技能点**：UI 异常先通过 devtools 确认真实 DOM 结构与呈现原因，再决定修复方向，避免臆测性 CSS。
- **坑点**：工具栏中部按钮「丢失」疑为图标/SVG 缺失，实际是抽屉宽度有限导致 flex 换行裁切，且截图拼接造成 DOM 错位误读。
- **解决方案**：让用户提供 .ql-toolbar 与 .ql-formats 完整 DOM，逐一比对渲染个数与容器归属后再定位真实 bug，不动手加猜测性样式。
- **拓展**：可沉淀为「现象→DOM→样式→代码」四步 UI 排查清单，适用于一切组件库 UI 异常。
- *来源：admin-workspace-new / 2026-08-12*

### 4. 事件冒泡与组件通用性
- **技能点**：共享组件保持行为纯净，业务特有的交互差异在调用侧用事件修饰符解决。
- **坑点**：CopyText 点击冒泡触发外层卡片 handleQuestionClick，试图在共享组件内 stopPropagation 反而破坏通用性。
- **解决方案**：在业务组件 questionCard.vue 给 CopyText 加 @click.stop，共享组件保持无事件参数、无拦截。
```text
<CopyText :text="`题目编号: ${data.questionId}`" :copyText="data.questionId" @click.stop />
```
- **拓展**：判断「修共享组件还是修调用方」的标准是：该行为是否所有使用者都想要。
- *来源：admin-workspace / 2026-08-11*

### 5. 状态单源简化同步链
- **技能点**：用单一布尔状态驱动面板显隐，而非维护两组互为镜像的可变状态；每个 UI 状态只由一个 ref 拥有。
- **坑点**：折叠标志与 panel sizes 数组互相映射，加上持久化/恢复逻辑后 watch 链复杂且易递归。
- **解决方案**：面板显隐直接用 <template v-if="isAiReviewer" #panel-2> 控制，sizes 退化为纯拖拽内部状态，删除双向同步与 storageKey。
```text
<template v-if="isAiReviewer" #panel-2>
  <FilePreviewPanel />
</template>
```
- **拓展**：任何「两份状态互为镜像」的设计都应审视：能否删除其一、让另一份成为唯一真相源。
- *来源：admin-workspace / 2026-08-11*

### 6. 线上现象对比部署分支
- **技能点**：排查线上/测试环境异常，先确认运行版本与本地工作区是否一致，再投入代码排查。
- **坑点**：手机扫码上传报 No static resource file/getStsToken，本地代码看似已修复，实际 v2 迁移只在未提交工作区，测试环境跑的是 master 旧码。
- **解决方案**：用 git show master:<文件> 对比部署分支内容，确认现象对应哪个版本再定位修复。
```text
git show master:src/service/upload.ts
```
- **拓展**：多副本/多环境开发应定期记录「部署分支 vs 本地未提交」差异，作为排障第一步。
- *来源：admin-workspace-hr / 2026-09-24*
