# 每日基础技术总结 · 2026-08-26 · Python 基础语法与数据结构

## 📚 今日主题

> **Python 基础语法与数据结构**（后端基础（Node.js / Java / Python））

### 1. 核心概念速览
Python 是一门动态类型、基于对象模型的解释型语言。其语法核心是以缩进划分块结构，所有实体均为对象，变量是名字到对象的引用绑定。内置数据结构（list、tuple、dict、set）本质是对象引用的容器：list 是动态数组，tuple 是不可变序列，dict 是哈希表，set 是哈希集合。这套语法与数据结构解决的核心问题，是在统一对象模型下以高表达力语法提供高效的数据组织和访问抽象。其底层机制是：源码先编译为字节码，由 CPython 虚拟机执行；类型在运行时动态解析，容器内部通过指向 PyObject 的指针数组或哈希表条目实现。在整个计算机/AI 体系中，Python 是 AI 生态的主语言，NumPy/PyTorch 等依赖 Python 层容器与 C 层内存缓冲的交互。专业工程师必须掌握这些结构的内存布局、时间复杂度和可变性语义，否则无法分析性能瓶颈、共享对象导致的 Bug 以及并发模型下的数据一致性。与前端 JS 相比，Python 的 list/dict 与 JS 的 Array/Map 表面相似，但底层实现和语义有本质差异，这些差异是跨语言工程的基本常识。

### 2. 底层原理剖析
1. 对象模型与变量绑定：Python 中的每个对象都有类型、引用计数和值。变量名是命名空间 dict 中的键，赋值语句将名字绑定到对象地址，因此多个名字可以指向同一对象。这与 JS 的引用类型类似，但差异在于 Python 没有原始值类型，整数和字符串也是对象；且 Python 通过引用计数回收内存，配合循环引用检测 GC。对象是否可变由类型决定：list/dict/set 可变，tuple/frozenset/str/int 不可变。
2. 序列的底层实现：CPython 的 PyListObject 是一个动态数组，结构上包含 ob_item（PyObject** 指针数组）、ob_size（当前长度）和 allocated（已分配容量）。append 在容量充足时仅写一个指针，均摊 O(1)；插入和删除需要移动后续指针，O(n)。tuple 则是固定长度指针数组，没有预留容量，因此更省内存且可哈希（当元素可哈希）。对比 JS 的 Array，V8 会优化为连续的同构元素数组（Packed Elements），而 Python list 始终是 PyObject* 数组，因此存储整数时每个元素实际是一个指向小整数对象的指针，内存占用显著更高。
3. 哈希表的实现：dict 是哈希表，CPython 3.6+ 采用紧凑布局，条目存储键、值、哈希值；查找时先计算键的哈希，再按哈希定位，冲突使用开放寻址或拉链法。键必须可哈希，即实现 __hash__ 和 __eq__，且其哈希值在对象生命周期内保持不变。这与 JS 的 Map 不同：Map 对对象键使用引用相等，不要求对象提供哈希；Python 的 dict 则要求键对象必须实现哈希和相等方法，且通常要求不可变。set 是只存键的哈希表，与 dict 的键视图同构。
4. 执行机制与类型系统：Python 代码先编译为字节码，由解释器逐条执行。例如 a += 1 在字节码层面是 LOAD_FAST、LOAD_CONST、BINARY_ADD、STORE_FAST，由于整数不可变，BINARY_ADD 创建一个新整数对象并重新绑定到 a。CPython 的小整数缓存（-5 到 256）在启动时预创建，因此这些整数的身份稳定。JS 中 V8 的 SMI 优化同样存在，但语义不同。Python 的 is 比较对象身份，== 比较值；前端工程师容易混淆的是，JS 的 === 对原始类型是值比较，对对象是身份比较，而 Python 的 == 默认调用 __eq__ 做值比较，两者需要区分。
5. 与前端概念的本质区别：Python 没有 TypeScript 那样的编译期接口。TS 的 interface 是结构类型，编译后不产生运行时代码；Python 的 Protocol（typing.Protocol）定义结构类型，且可通过 @runtime_checkable 在运行时检查，但本质仍是鸭子类型。Python 的抽象基类（abc.ABC）则类似 Java 的接口，可声明抽象方法并阻止实例化。前端工程师需要理解：Python 的类型注解仅用于静态检查工具（如 mypy），运行时不会强制类型，这与 TS 的编译期擦除类型在时间点上有差异，但都非运行时强制。

### 3. 基础代码与实战验证
```text
# 演示变量绑定与对象共享
lst1 = [1, 2]
lst2 = lst1      # 将同一对象的地址绑定到 lst2，不复制 list
lst2.append(3)   # 通过 lst2 修改对象
print(lst1)      # [1, 2, 3]，lst1 和 lst2 是同一对象的两个名字

# 演示 dict 键的哈希相等性
d = {}
d[1] = 'a'       # 键 1 的哈希值为 hash(1)
d[True] = 'b'    # hash(True) == hash(1) 且 True == 1，因此覆盖前一项
print(d)         # {1: 'b'}，只保留一个条目

# 演示 tuple 的浅层不可变性
t = ([1], 2)
t[0].append(99)  # 元组本身不可变，但其元素 list 是可变对象
print(t)         # ([1, 99], 2)

# 演示 CPython 小整数缓存
a = 256
b = 256
print(a is b)    # True：小整数 -5 到 256 在解释器启动时预创建，同一对象
```

### 4. 常见误区与进阶思考
误区 1：认为变量有类型，并据此设计代码。实际上 Python 的变量只是名字，类型属于对象。典型错误是使用可变对象作为函数默认参数：def f(x=[]): ... 默认 list 在函数定义时创建一次，所有调用共享同一对象，导致跨调用状态污染。前端工程师容易类比 JS 的默认参数，但 JS 中默认参数每次调用都会新建对象，而 Python 不是。
误区 2：认为 dict 的键只需要相等性比较，忽略哈希。Python 的哈希表先算哈希再比对相等，因此键对象必须同时正确实现 __hash__ 和 __eq__。如果只重写 __eq__ 不重写 __hash__，实例的哈希值退化为 id 的哈希，导致相等的对象（按 __eq__ 相等）在 dict 中存为两个条目，破坏字典语义。前端工程师可对比 JS Map：Map 不要求对象提供哈希，但使用引用相等，因此不会有此问题。
思考题：自定义类 C 只重写 __eq__ 不重写 __hash__，其实例作为 dict 的键会出现什么现象？请结合哈希表的“哈希-定位-相等确认”流程，解释为什么 __eq__ 和 __hash__ 必须一致，并说明如何修复。
