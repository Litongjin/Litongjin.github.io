# 每日基础技术总结 · 2026-05-22 · HNSW 的层级图结构：构建与搜索

## 📚 今日主题

> **HNSW 的层级图结构：构建与搜索**（AI 开发基础）

### 1. 核心概念速览
HNSW（Hierarchical Navigable Small World）是一种基于多层可导航小世界图的近似最近邻（ANN）索引结构。其本质是构造一个概率分层的图，其中高层图为稀疏的'远跳'连接，低层图为稠密的'近邻'连接，从而将搜索过程从'逐点比较'转化为'由粗到细的层级导航'。它解决了在高维欧氏空间（或其他度量空间）中，无法使用传统树索引（如KD-Tree）有效支持维度灾难场景下的最近邻查询问题，以牺牲少量精度换取查询延迟和吞吐量的数量级提升。核心机制是：每个节点以指数递减概率被分配到若干层，插入时从顶层到底层逐层贪心搜索并建立双向边；查询时从最高层入口出发，每层执行贪心下降，到达底层后使用优先队列扩展候选集。在AI体系中，它是向量检索/RAG、推荐系统、多模态搜索等场景的核心索引组件。专业工程师必须理解其层级结构、距离度量、图连通性对召回率与延迟的影响，否则无法针对数据分布和QPS要求进行索引调优，也无法设计分布式向量检索系统。

### 2. 底层原理剖析
底层机制由构建与搜索两部分构成。

**构建**：设全局最大层为L_max，节点x插入时，用几何分布随机采样其最大层数l_x，使得P(l_x = k) ∝ exp(-k/λ)。采样后，x在0..l_x层均出现。插入过程从当前全局入口点ep_global开始，在每一层l = l_x down to 0执行：1) 在当前层l上，从ep_start开始做贪心搜索（反复比较邻居距离，移动到更近节点直到局部最优），得到最优点c_l；2) 在c_l与x之间建立双向边，并按照每层最大度数M_l进行边剪枝（仅保留最相似的M_l个邻居）；3) 将ep_start更新为c_l，进入下一层。注意，如果l_x > L_max，则x成为新的全局入口点。

**搜索**：查询向量q从全局入口点ep_global开始，从最高层l = L_max向底层逐层执行：在当前层l上，从当前节点出发做贪心搜索（这里使用优先级队列实现Beam Search，保持ef个候选），得到该层最优点ep_l；然后以ep_l为起点进入下一层。到达底层l=0后，再做一次更宽度的搜索（ef_search个候选），最终从候选集中返回topK个最近邻。

**本质对比**：HNSW的层级结构可类比前端开发中的'多级缓存'模型（如Memory Cache → Service Worker → HTTP Cache），但二者有本质区别：多级缓存是逐级查完就回源，级间存在包含关系；而HNSW每层都是全量节点的随机子集，层间通过节点的'同时存在'以及搜索时逐层传递起点来协作，且搜索过程不严格按'命中'终止，而是逐层优化。HNSW更接近'跳表'的概率层级思想，但跳表是链表结构，HNSW是图结构，支持多邻居跳转。前端的模块依赖图（Webpack）是静态有向图，边代表依赖；HNSW是动态无向图，边代表度量距离，两者都是图，但边的语义和构建方式完全不同。

### 3. 基础代码与实战验证

```text
以下为HNSW构建与搜索的核心伪代码，直接映射上述原理。

构建插入：

function insert(node):
  l_node = random_level()          // 采样节点最大层，概率随层高指数衰减
  ep = global_entry_point           // 从全局入口点开始
  for l = l_node down to 0:         // 逐层向下
    ep_l = greedy_search(node, ep, l) // 在层l执行贪心，返回最近节点
    connect_bidirectional(ep_l, node, l) // 建立双向边
    prune_edges(ep_l, l)           // 剪枝：仅保留距离最近的M个邻居
    ep = ep_l                      // 将本层结果作为下一层起点
  if l_node > global_max_level:     // 若节点出现在更高层
    global_entry_point = node       // 更新全局入口点

搜索查询：

function search(q, topK):
  ep = global_entry_point
  for l = global_max_level down to 0:  // 从最高层向底层
    ep = greedy_search(q, ep, l)       // 每层贪心，逐层逼近
  candidates = priority_queue(ep)      // 底层启动优先队列
  for each candidate in beam_search(q, candidates, ef_search): // 扩展候选
    add_to_result if distance small
  return topK from result

关键点：贪心搜索时，每次从当前节点出发，比较所有邻居与目标向量的距离，移动到距离最小的邻居，直到邻居都不优于当前节点。底层优先队列则保持多个候选，避免贪心陷入局部最优。

验证步骤：用少量随机向量（如1000个）构建上述图，设置L_max=5，M=16，ef_construction=100，然后随机生成100个查询，对比HNSW结果与暴力线扫结果，观察召回率与查询耗时随ef_search的变化。
```

### 4. 常见误区与进阶思考
**误区1**：将HNSW的层级结构误解为树结构，认为搜索是从根节点向下走分支。实际上，HNSW每层是一个独立的图（底层全量，上层稀疏子集），搜索是逐层贪心，而不是树的分支决策。高层的贪心结果只是为低层提供一个起点，并不决定最终路径。

**误区2**：认为图边越多越好，盲目增大每层最大度M。实际上，过大的M会破坏小世界图的'导航性'，增加存储和遍历开销，并可能使贪心搜索陷入局部最优；过小的M则导致图连通性差，召回率下降。M的选取需要根据数据维度、分布和查询性能要求进行权衡。

**思考题**：假设某查询向量q在高层贪心时陷入了一个局部最优点p（即p的所有高层邻居都比p离q远），但p在低层有邻居p'，p'比p更接近q。请解释：为什么在高层搜索结束后，以p为起点进入低层，仍然能够找到p'？这体现了HNSW层级结构的什么本质特性？
