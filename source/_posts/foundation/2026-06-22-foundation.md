# 每日基础技术总结 · 2026-06-22 · 并查集的按秩合并与路径压缩复杂度

## 📚 今日主题

> **并查集的按秩合并与路径压缩复杂度**（算法与数据结构）

### 1. 核心概念速览
并查集（Disjoint Set Union, DSU）是一种维护元素所属集合的数据结构，支持两种操作：查找（Find）确定元素所在集合的代表元，合并（Union）将两个集合合并。按秩合并（Union by Rank）与路径压缩（Path Compression）是两种互补的优化策略。按秩合并保证每次合并时，将秩（树高上界）较小的根连接到秩较大的根上，从而控制树高增长；路径压缩在查找过程中将路径上的节点直接指向根，扁平化树结构。两者结合后，单次操作的均摊时间复杂度为反阿克曼函数 O(α(n))，在实用范围内近似常数。该结构是图连通性、最小生成树（Kruskal）、离线 LCA、动态连通性等算法的基石，也是理解『均摊分析』与『势能法』的最佳入门案例。专业工程师必须掌握它，因为它在处理大规模数据关联、网络连接检测、图像分割（如并查集实现连通域标记）以及 AI 中的聚类后处理中高频出现，且其复杂度分析体现了从直觉到严格理论的核心思维模式。

### 2. 底层原理剖析
底层机制分为两部分：
1. 按秩合并：每个集合根节点维护一个『秩』（rank），通常定义为树高的上界。初始时每个元素的秩为0。合并时比较两个根的秩，将秩较小的根作为子树连接到秩较大的根上；若秩相等，则任选一个根作为新根，并将其秩加1。该策略保证任意树的树高不超过 log n（n为元素数），因为每层节点数至少翻倍。
2. 路径压缩：在 Find(x) 过程中，递归或迭代地遍历从 x 到根的路径，并将沿途所有节点的父指针直接指向根。这不会改变集合的划分，但显著降低后续操作路径长度。路径压缩与按秩合并协同时，秩不再是精确树高，而是树高的上界，但该上界仍然有效。
3. 复杂度本质：单独使用按秩合并，Find 最坏 O(log n)；单独使用路径压缩，最坏 O(log n) 均摊。两者结合后，通过势能分析（引入 Schecker 的 Ackermann 函数逆），证明任意 m 次操作（含 n 次 makeSet）的复杂度为 O(m α(n))，其中 α 为反阿克曼函数。该结论的关键在于：路径压缩每次减少的节点深度与秩的增长之间形成精确的势能抵消，使得总消耗受 α(n) 控制。
与前端已有概念的对比：前端开发中常见的『React 状态更新合并』或『Redux 不可变数据更新』也涉及将多个操作合并以减少重复计算，但那是数据流层面的优化；并查集的优化是数据结构内部指针重定向，更接近编译器中『支配树』或『SSA 形式』的指针扁平化思想。另外，Java 的接口与 TS 的接口区别在于运行时是否保留类型信息，而并查集的秩与父指针是运行时数据，与类型系统无关；但两者都体现了『约定优于实现』——秩作为上界保证性能，接口作为契约保证类型安全。

### 3. 基础代码与实战验证
```text
以下为极简并查集实现（Python），包含按秩合并与路径压缩。

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))  # 父指针，初始时每个元素自成一集合，根指向自己
        self.rank = [0] * n          # 秩，即树高上界，初始为0

    def find(self, x):
        # 路径压缩：递归查找根，并将路径上所有节点直接连接到根
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # 关键：递归返回根，同时把当前节点挂到根上
        return self.parent[x]

    def union(self, x, y):
        root_x = self.find(x)  # 查找 x 的根，并压缩路径
        root_y = self.find(y)  # 查找 y 的根，并压缩路径
        if root_x == root_y:
            return  # 已属于同一集合，无需合并
        # 按秩合并：将秩小的根连到秩大的根上
        if self.rank[root_x] < self.rank[root_y]:
            self.parent[root_x] = root_y  # 将 x 的根挂到 y 的根下
        elif self.rank[root_x] > self.rank[root_y]:
            self.parent[root_y] = root_x
        else:
            # 秩相等，任选一个作为新根，新根秩+1
            self.parent[root_y] = root_x
            self.rank[root_x] += 1

验证：
初始化后依次执行 union(0,1), union(2,3), union(1,3) 后，find(0) 返回根；通过 rank 可观察树高保持低矮。该实现是后续所有复杂并查集变体的基础。
```

### 4. 常见误区与进阶思考
常见误区1：认为路径压缩后秩必须严格等于树高。实际上秩仅是树高的上界，路径压缩可能使实际树高远小于秩，但这不影响复杂度上界。若为节省空间动态调整秩，反而可能破坏均摊分析的正确性。
常见误区2：认为按秩合并与路径压缩互相替代。它们各自优化不同维度——按秩合并控制合并方向，路径压缩加速查找；两者结合才产生 O(α(n)) 的接近常数复杂度。只用一个则最坏复杂度仍可达 O(log n)（按秩）或 O((m+n)log n)（仅压缩）。
深度思考题：如果合并时不用按秩，仅用随机合并（如总是将第二个根挂到第一个根下），同时每次 find 做路径压缩，那么 m 次操作的均摊复杂度是多少？尝试用势能函数构造证明它仍为 O(m log n)，并指出这个 log n 的常数因子来自哪里——这能检验你是否真正理解路径压缩的势能机制。
