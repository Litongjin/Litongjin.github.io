# 每日基础技术总结 · 2026-08-18 · V8 老生代 GC 的三色标记与增量标记（Incremental Marking）

## 📚 今日主题

> **V8 老生代 GC 的三色标记与增量标记（Incremental Marking）**（前端底层与计算机基础）

### 1. 核心概念速览
V8 老生代 GC 中的三色标记是一种基于图着色的增量标记算法，用于在标记-压缩（Mark-Compact）回收中安全地追踪存活对象。它将对象划分为三种状态：白色（未访问）、灰色（已访问但引用未完全扫描）、黑色（已访问且所有引用均已扫描）。其核心目的是允许标记过程与 JavaScript 执行（mutator）交替进行，避免因并发修改对象图导致漏标（将存活对象误判为死亡）。增量标记（Incremental Marking）是 V8 将一次完整的标记任务拆分为多个小步进（step），穿插在程序执行中，并借助写屏障（write barrier）维护三色不变量，从而显著降低单次 GC 的停顿时间（pause）。该机制位于 V8 引擎的垃圾回收子系统，属于内存管理的底层核心。专业工程师必须掌握它，因为 JS 内存性能、内存泄漏的根因、GC 停顿优化、弱引用语义（WeakMap）等均与此直接相关，是前端深入底层不可回避的基础。

### 2. 底层原理剖析
三色标记的底层运行机制可抽象为以下过程：
1. 初始化：所有对象标记为白色，根集合（全局对象、执行栈、寄存器、内建对象等）中的直接引用对象被标记为灰色，并压入标记栈。
2. 扫描：从标记栈弹出一个灰色对象，遍历其所有字段，若子对象为白色，则将其标记为灰色并压栈；当前对象所有子对象处理完毕后，将其标记为黑色。
3. 终止：当标记栈为空时，标记完成。所有白色对象不可达，将回收。

增量标记的核心难点是 mutator 在标记期间会修改引用关系。若不保护，可能发生黑对象新增指向白对象的引用，而该白对象原本不在标记路径上，导致其被错误回收。为此 V8 使用写屏障（store barrier）维持强三色不变量：禁止黑色对象直接引用白色对象。写屏障在每次对象属性写入时执行：如果被写入属性所在对象是黑色，且新值是白色，则将该新值强制标记为灰色并压入标记栈，使其变为可扫描状态。这样保证了所有从黑对象可达的白对象都会被重新标灰并最终标黑。

增量标记的调度采用步进（incremental step）机制：V8 在安全点（如对象分配、函数进入/退出、循环等）插入标记步骤，每次执行固定工作量（如扫描一定数量的对象或引用），然后交还控制权给 JS。整个标记阶段分布在多个任务中，最终标记完成时可能还有并发标记（concurrent marking）阶段，由多个辅助线程并行处理剩余标记工作。

与前端已有概念的异同：前端事件循环将长任务拆分为宏任务和微任务以避免阻塞渲染，增量标记同样是将长标记任务切分，避免长时间阻塞主线程——二者都是时间分片思想，但事件循环的调度粒度由消息队列和优先级决定，而增量标记的粒度由 GC 的字节/对象预算决定。前端浏览器渲染引擎的增量布局（incremental layout）也是类似策略，将布局计算分块与样式计算/绘制交替。三色标记与前端“脏检查”（如 Angular 的 Zone.js 标记）本质不同：脏检查是应用层变更检测，三色标记是 GC 层对象图可达性分析，前者可被优化为增量，后者必须依赖写屏障保证正确性。另外，TS 的 interface 与 Java 的 interface 的差异是类型系统层面的静态结构问题，与三色标记无关，但同样体现了“同一概念在不同抽象层的定义差异”——三色标记在 V8 与 JVM 中的具体实现（写屏障类型、屏障指令成本）也各有不同。

### 3. 基础代码与实战验证
```text
以下代码用 JavaScript 模拟 V8 三色标记的核心算法（非增量，但展示三色转换），以及通过 Node.js 命令行观察增量标记日志的方法。

模拟三色标记（极简版）：
const WHITE = 0, GREY = 1, BLACK = 2;
function simulateMark(root) {
  const color = new Map();
  const stack = [];
  // 收集从 root 可达的所有对象（此处假定对象有 refs 数组）
  const objects = collectAll(root);
  for (const obj of objects) color.set(obj, WHITE); // 初始全白
  color.set(root, GREY); stack.push(root);          // 根标灰入栈
  while (stack.length > 0) {
    const obj = stack.pop();
    for (const child of obj.refs) {
      if (color.get(child) === WHITE) {             // 白子对象标灰
        color.set(child, GREY);
        stack.push(child);
      }
    }
    color.set(obj, BLACK);                          // 所有引用扫描完毕，标黑
  }
  return color; // 白对象即不可达
}
```

### 4. 常见误区与进阶思考
常见误区1：认为三色标记中白色对象一定不可达。实际上白色对象只是“在当前标记进度下未被访问到”，在增量标记中可能因为写屏障被重新标灰而存活。只有在标记结束仍是白色的对象才不可达。
常见误区2：认为增量标记完全不需要停顿，或以为写屏障是额外开销可忽略。写屏障会修改每个对象属性写入路径，带来一定性能损耗；且增量标记结束后仍有“标记完成”和“压缩”等阶段，需要暂停 JS 执行。

进阶思考题：如果 V8 使用强三色不变量，那么当 mutator 将一个黑色对象 A 的字段赋值为一个白色对象 B，且 B 是刚从灰对象 C 的引用中移除并改为被 A 引用时，写屏障将 B 标灰。请分析：在这种情况下，若写屏障仅将 B 标灰但未将 B 的白色子对象 D 标灰，是否可能发生 D 被误回收？请结合三色不变量与扫描顺序说明为什么需要将 D 也置为灰色（或为什么不需要）。
