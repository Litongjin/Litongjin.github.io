# 每日基础技术总结 · 2026-06-27 · 服务端模板注入 SSTI 的沙箱逃逸与构造

## 📚 今日主题

> **服务端模板注入 SSTI 的沙箱逃逸与构造**（安全基础）

### 1. 核心概念速览
服务端模板注入（SSTI）是指服务端模板引擎将用户可控输入直接作为模板表达式或模板结构解析执行，导致攻击者能够注入模板语法，进而读取上下文数据、调用内部对象甚至执行任意代码。其本质是数据与代码的边界混淆：模板引擎的解析器将用户输入中的特殊字符序列（如 {{ }}、${} 等）识别为代码 AST 节点，而非纯文本。该漏洞解决的核心问题是服务端渲染场景下，如何通过模板表达式获得对后端执行环境的控制。SSTI 是注入类攻击的一种，与 SQL 注入同源，但目标解析器是模板引擎。它属于 Web 安全中的服务端漏洞，同时也涉及沙箱逃逸技术。专业工程师必须掌握它，因为现代应用大量使用 Jinja2、Twig、Freemarker 等模板引擎，且微服务、低代码平台、AI 生成模板等场景都会引入模板渲染，理解其底层机制才能在设计模板时避免注入面，并能在安全审计中识别和利用此类漏洞。

### 2. 底层原理剖析
模板引擎的渲染过程本质上是：模板字符串 → 词法分析生成 token → 语法分析生成 AST → 编译成可执行代码（Python 字节码 / JS 函数）→ 在指定上下文中执行。SSTI 发生在 AST 构建阶段：用户输入被拼接到模板字符串中，其中的模板表达式被解析为 AST 节点，最终编译为执行指令。沙箱是模板引擎用于限制表达式可访问对象集合的机制，通常通过代理（proxy）或过滤属性访问实现。以 Jinja2 沙箱为例，它重写了 getattr 和 getitem，阻止访问以下划线开头的属性（如 __class__）。但 Python 对象模型提供了绕过路径：从任何对象（如字符串、数字）出发，通过 __class__ 获得其类型，再通过 __mro__ 获得继承链，最终到达 object；然后调用 __subclasses__() 获取进程内所有类的子类列表，从中筛选出危险类（如 subprocess.Popen 或 os._wrap_close）进而执行系统命令。这种逃逸的本质是：沙箱限制的是特定属性名，但 Python 的反射机制允许从任意对象实例回溯到类型系统，从而获得全局类注册表。对比前端已有概念：前端模板字符串（如 JS 的 ${}）如果被 eval 或 new Function 执行，类似 SSTI；而浏览器中可以通过 ({}).constructor.constructor('return process')() 访问 Function 构造函数，这与 Python 的 __class__ 链异曲同工。但前端没有沙箱概念，浏览器本身也是沙箱，而服务端沙箱需要阻止访问宿主系统 API。

### 3. 基础代码与实战验证
```text
以下代码用纯 Python 模拟一个极简模板渲染引擎，并展示沙箱逃逸链。


def render(template, context):
    # 仅解析单个 {{ expression }}，提取表达式内容
    start = template.find('{{') + 2
    end = template.find('}}', start)
    expr = template[start:end].strip()
    # 受限全局命名空间，禁用内建函数 __builtins__
    safe_globals = {'__builtins__': {}}
    return str(eval(expr, safe_globals, context))

# 攻击者控制的模板输入
payload = '{{ [].__class__.__mro__[1].__subclasses__() }}'
# 渲染，将输出所有已加载类的列表
print(render(payload, {}))


注释：
- `[].__class__` 获取列表类型 `list`。
- `__mro__[1]` 获取 `list` 的父类 `object`（Python 3 中 `list.__mro__` 是 `(list, object)`）。
- `object.__subclasses__()` 返回进程内所有已加载类的子类列表，这是逃逸的关键一步。
- `eval` 的命名空间禁用 `__builtins__`，但攻击者仍能通过对象链访问危险类，说明沙箱不能只靠限制内建函数。
```

### 4. 常见误区与进阶思考
常见误区：
1. 认为过滤用户输入中的 `__class__`、`__subclasses__`、`os` 等关键词就能防止 SSTI。实际上，模板引擎的求值过程发生在服务端，用户输入可以被编码、拼接、利用模板自身的过滤器（如 Jinja2 的 `attr`）动态构造属性名，过滤黑名单极易被绕过。
2. 认为沙箱环境是绝对安全的。沙箱通常只是对属性访问做黑名单或白名单，但 Python 的对象模型允许从任意对象出发通过 `__class__`、`__mro__`、`__subclasses__` 获得全局类注册表，进而找到危险类；这本质上是语言反射能力与沙箱约束之间的不对称。

思考题：
请解释在 CPython 中，`object.__subclasses__()` 为何能返回所有直接继承自 object 的类列表？从 `PyTypeObject` 的 `tp_base` 和 `tp_subclasses` 字段出发，分析 `__subclasses__` 的实现机制，并说明这种基于类型对象链表的全局注册表为什么是沙箱逃逸的根本原因。
