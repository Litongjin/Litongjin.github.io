# 每日基础技术总结 · 2026-10-10 · 单调栈与单调队列

## 📚 今日主题

> **单调栈与单调队列**（算法与数据结构（面试））

### 1. 核心概念速览
单调栈与单调队列不是新的容器，而是在普通栈/双端队列上附加“元素值单调不变量”的访问策略。单调栈：栈内元素（或下标指向的值）自底向顶保持单调递增或递减，push 前弹出所有破坏单调性的栈顶；用于线性时间求最近更大/更小元素、确定区间边界。单调队列：双端队列内元素自队首到队尾保持单调，队首维护区间最值，队尾维护单调性，并按元素生命周期淘汰过期项；用于线性时间求滑动窗口最值。核心机制是将暴力 O(n²) 的两两比较压缩为均摊 O(n)：每个下标至多入栈/入队一次、出栈/出队一次，通过单调不变量丢弃不可能再成为答案的候选。它在算法体系中属于线性序列偏序比较的基础优化结构，也是动态规划斜率优化、图像局部极值、受限窗口局部约束等更复杂机制的底层构件。专业工程师掌握它，是区分“会调 API”与“能分析均摊复杂度与不变量”的基本线。

### 2. 底层原理剖析
单调栈运行机制（以求下一个更大元素、栈底到栈顶值不增为例）：
1. 栈中存下标，栈底到栈顶对应 nums 值不增。
2. 遍历到 i 时，若 nums[i] 大于栈顶值，则栈顶元素第一次遇到右侧更大值，弹出栈顶并记录 ans[top] = nums[i]；重复比较。
3. 当栈空或栈顶值不再小于 nums[i] 时，将 i 入栈。
不变量：栈内元素尚无右侧更大值，且值自底向顶不增；弹栈时当前元素是弹出元素右侧第一个更大元素，弹出后的新栈顶是左侧最近一个不小于弹出值的候选。每个元素只入栈一次、出栈一次，均摊 O(n)。

单调队列运行机制（以滑动窗口最大值为例）：
1. 双端队列存下标，队首到队尾对应 nums 值递减。
2. 右移窗口前，若队首下标小于窗口左边界 i-k+1，则从队首淘汰过期元素。
3. 新下标 i 从队尾进入前，弹出所有队尾值 ≤ nums[i] 的下标，保持递减。
4. 队首下标指向当前窗口最大值。
每个下标至多入队/出队一次，均摊 O(n)。

与前端已有知识对比：JavaScript 的 Array.prototype.push/pop 提供 LIFO，push/shift 提供 FIFO，但语言只约束操作端点，不校验内容；单调栈/队列相当于在运行时对元素值附加偏序约束，违反约束即触发淘汰。这类似 TypeScript 的 interface 在 JS 运行时行为之上增加编译期结构约束，不改变底层数组/对象存储；区别在于单调性约束是运行时维持的，直接影响候选集裁剪。

### 3. 基础代码与实战验证
```text
// 单调递减栈：求每个元素右侧第一个更大元素（值）
function nextGreaterElement(nums) {
  const n = nums.length;
  const ans = new Array(n).fill(-1);
  const stack = []; // 存下标；栈底到栈顶对应 nums 值不增
  for (let i = 0; i < n; i++) {
    // 当前值大于栈顶值：栈顶元素第一次遇到右侧更大值
    while (stack.length && nums[stack[stack.length - 1]] < nums[i]) {
      const top = stack.pop();
      ans[top] = nums[i]; // 记录右侧第一个更大值
    }
    stack.push(i); // 当前值不大于栈顶值或栈空，入栈保持不增
  }
  return ans;
}

// 单调递减双端队列：滑动窗口最大值
function maxSlidingWindow(nums, k) {
  const n = nums.length;
  const res = [];
  const q = []; // 存下标；队首到队尾对应 nums 值递减
  let head = 0; // 逻辑队首；避免 Array.shift 搬运导致的 O(n)
  for (let i = 0; i < n; i++) {
    // 1. 删除窗口外过期下标：窗口左边界为 i-k+1
    if (head < q.length && q[head] <= i - k) head++;
    // 2. 队尾值小于等于当前值，则不再可能成为后续窗口最大值
    while (q.length > head && nums[q[q.length - 1]] <= nums[i]) {
      q.pop(); // 只删队尾；逻辑队首由 head 维护
    }
    q.push(i); // 当前下标从队尾进入
    // 3. 窗口形成后，逻辑队首就是当前窗口最大值下标
    if (i >= k - 1) res.push(nums[q[head]]);
  }
  return res;
}
```

### 4. 常见误区与进阶思考
误区一：只存值不存索引或生命周期，尤其是单调队列。滑动窗口问题中如果队列只存值，无法判断队首是否滑出窗口；单调栈若不存下标，也无法在弹栈时计算左右边界。实现时若用 JavaScript Array.shift 删除队首，Array.shift 会搬运剩余元素，整体复杂度可能退化到 O(n²)，工程实现应使用 head 指针或真正的双端队列。

误区二：混淆等值策略导致边界错误。比较时用 >=/> 或 <=/< 决定相同元素是否弹出，直接影响“严格”与“非严格”语义。求下一个严格更大元素时，通常用 nums[top] < nums[i] 弹栈；若写成 <=，会把相等也当作更大的答案。大量重复值、全部相等、窗口未满等边界场景必须先明确单调方向与等值处理。

进阶思考：给定柱状图高度数组 heights，要求 O(n) 找最大矩形面积。用单调递增栈（栈底到栈顶高度不降）遍历：当 heights[i] 小于栈顶高度时，栈顶柱子的右边界确定为 i，左边界为弹出后的新栈顶下标（或 -1），其最大可扩展矩形面积即可算出；随后将 i 入栈。请推导为何新栈顶是左边界，并说明等值柱子是否会导致面积遗漏或重复计算。若改为求所有子数组最小值的和，弹栈时如何用左右距离计算该高度作为最小值的子数组数量？
