# 每日基础技术总结 · 2026-02-22 · 词法环境、作用域链与闭包 Context

## 📚 今日主题

> **词法环境、作用域链与闭包 Context**（前端底层与计算机基础）

### 1. 核心概念速览
词法环境（Lexical Environment）是 ECMAScript 规范定义的内部结构，由环境记录（Environment Record）和对外部词法环境的引用（outer reference）组成，用于存储作用域内绑定的标识符。作用域链（Scope Chain）是词法环境通过 outer 引用形成的链式结构，变量解析（Identifier Resolution）即沿着该链逐层查找。闭包（Closure）是函数对象与其定义时词法环境的组合，函数通过内部槽 [[Environment]] 保存该环境，使得函数在定义作用域之外执行时仍能访问捕获的变量。其本质是静态作用域（词法作用域）的实现机制，解决了变量查找规则、变量隔离与生命周期扩展问题。在计算机体系结构中，它属于语言运行时的执行上下文管理范畴，是理解变量提升、函数执行、内存管理（GC 的引用路径）的基石。专业工程师必须掌握，因为它直接决定代码行为、性能分析和内存泄漏排查能力，且是后端、AI 等场景中函数式编程、装饰器、依赖注入等抽象的基础。

### 2. 底层原理剖析
以函数为例。函数声明时，JS 引擎创建函数对象，并设置其内部槽 [[Environment]] 为当前正在执行的词法环境（即定义处的环境）。当函数被调用时，引擎创建新的执行上下文，并为其创建新的词法环境（称为 LE_call），LE_call 的环境记录包含形参、局部变量、arguments 等，其 outer 引用被赋值为函数的 [[Environment]]。于是调用环境与定义环境通过 outer 链连接，形成作用域链。变量解析时，引擎从当前 LE_call 的环境记录开始查找，若未命中则沿 outer 引用逐级向上，直到全局环境。若全局仍未命中，在非严格模式下隐式创建全局变量，严格模式则抛出 ReferenceError。闭包的形成不依赖特殊语法，只要内部函数引用外部变量，且内部函数被返回或保存，其 [[Environment]] 就使外部变量被闭包引用，从而避免被 GC 回收。与前端已有概念对比：词法环境是运行时数据结构，而 TypeScript 接口、Java 接口是编译期类型约束；前者决定变量在内存中如何存储与解析，后者决定类型系统如何校验赋值兼容性。二者处于不同抽象层，但都服务于代码结构约束——词法环境约束了名称解析的范围，接口约束了形状匹配。JS 中的词法环境类似其他语言的符号表（symbol table），但动态创建、可捕获，而接口是静态的类型契约。

### 3. 基础代码与实战验证
```text
function createCounter() {
  let count = 0;          // 创建环境记录，绑定 count = 0
  return function inc() { // inc 函数的 [[Environment]] 指向 createCounter 的词法环境
    count++;              // 解析 count：先在 inc 自身环境查找，未命中则沿 outer 链向上
    return count;
  };
}
const counter = createCounter(); // 调用 createCounter 后，其词法环境被返回的 inc 引用，不会回收
console.log(counter()); // 输出 1
console.log(counter()); // 输出 2
```

### 4. 常见误区与进阶思考
误区一：认为闭包捕获的是变量的值（value）而非变量绑定（binding）。实际上，闭包捕获的是变量本身（即环境记录中的绑定），因此共享同一绑定的多个闭包会互相影响。误区二：认为作用域链是动态作用域，由调用位置决定。实际上它由定义位置决定，与调用栈无关。思考题：在循环体中使用 var 声明 i 并创建多个闭包，为什么最终输出都是循环结束后的值？如果改用 let 声明，结果如何？请从词法环境与绑定的角度解释。这验证是否理解每个循环迭代是否创建新的词法环境以及绑定如何捕获。
