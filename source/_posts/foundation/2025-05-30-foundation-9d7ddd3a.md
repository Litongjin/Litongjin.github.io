# 每日基础技术总结 · 2025-05-30 · 并查集：按秩合并与路径压缩

## 📚 今日主题

> **并查集：按秩合并与路径压缩**（算法与数据结构（面试））

### 1. 核心概念速览
并查集（Disjoint Set Union, DSU）是一种用于管理不相交集合（Disjoint Sets）的树形数据结构，核心解决动态连通性问题。其本质是通过维护一组元素的所属集合标识，支持高效的合并（Union）与查询（Find）操作。在计算机体系位置中，它是图论算法（如最小生成树 Kruskal 算法）的基础组件，也是 AI 领域关系推理、聚类分析的高效索引结构。专业工程师必须掌握它，因为其在 O(α(n)) 时间复杂度下处理大规模动态连通性检查，远超通用图遍历的性能瓶颈。

1. **核心机制**：每个集合由一棵树表示，根节点代表集合标识。初始化时每个元素自成一树。
2. **解决的问题**：快速判断两个元素是否属于同一集合；快速合并两个集合。
3. **为什么重要**：相比 BFS/DFS 每次 O(V+E) 的连通性检查，DSU 将均摊复杂度降低至近乎常数级，适合海量数据迭代处理。

### 2. 底层原理剖析
并查集的性能优化依赖于两个关键策略：按秩合并（Union by Rank）与路径压缩（Path Compression）。

1. **按秩合并（逻辑层级平衡）**：
   - **定义**：‘秩’（Rank）近似表示树的高度。合并两个集合时，总是将秩较小的树的根节点指向秩较大的树的根节点。
   - **机制**：确保树的高度增长缓慢，避免退化为链表。这与前端 TS 中的‘类型继承’不同，TS 接口是编译时静态约束，而 DSU 的秩是运行时动态维护的元数据，用于控制数据结构的物理形态（树高），而非语义。

2. **路径压缩（空间扁平化）**：
   - **定义**：在执行 Find 操作时，将查找路径上的所有节点直接连接到根节点。
   - **机制**：牺牲单次 Find 的时间以换取后续所有操作的时间。这使得树极其扁平，几乎成为单层结构。

3. **数学本质**：
   - 结合两种策略后，m 次操作对 n 个元素的时间复杂度为 O(m * α(n))，其中 α(n) 是阿克曼函数的反函数，增长极慢，实际应用中可视为常数 4。

4. **对比前端概念**：
   - **JS Object vs DSU Parent Array**：JS 对象通过哈希表建立 Key-Value 映射，时间复杂度 O(1) 但空间开销大且不支持动态合并；DSU 使用数组模拟树结构，空间紧凑（O(n)），通过指针（索引）间接引用实现合并，更适合密集连接的图结构存储。

### 3. 基础代码与实战验证
```text
// 并查集基础实现：按秩合并 + 路径压缩
// 使用数组 parent[i] 表示 i 的父节点，rank[i] 表示 i 的秩（近似高度）

class UnionFind {
    constructor(n) {
        // 初始化：每个节点独立成集合，自身为父，秩为 0
        this.parent = new Array(n).fill(0).map((_, i) => i);
        this.rank = new Array(n).fill(0);
    }

    // 查找根节点，同时进行路径压缩
    find(x) {
        if (this.parent[x] !== x) {
            // 递归查找根节点，并将当前节点 x 的父节点直接指向根节点
            // 这一步实现了路径压缩：压缩后的树结构变平，后续查询更快
            this.parent[x] = this.find(this.parent[x]);
        }
        return this.parent[x];
    }

    // 合并两个集合
    union(x, y) {
        const rootX = this.find(x);
        const rootY = this.find(y);

        if (rootX === rootY) return false; // 已在同一集合，无需合并

        // 按秩合并：将矮树挂载到高树下，保持整体树高尽可能低
        if (this.rank[rootX] > this.rank[rootY]) {
            this.parent[rootY] = rootX;
        } else if (this.rank[rootX] < this.rank[rootY]) {
            this.parent[rootX] = rootY;
        } else {
            // 秩相等时，任选其一作为父节点，并将该节点秩加 1
            this.parent[rootX] = rootY;
            this.rank[rootY] += 1;
        }
        return true;
    }
}
```

### 4. 常见误区与进阶思考
1. **误区：混淆‘秩’与‘真实高度’**：许多开发者认为 rank 就是树的实际深度。实际上，由于路径压缩的存在，树的实际高度可能在任意时刻被大幅压缩，rank 仅是一个上界估计值或历史最高高度的记录。依赖 rank 进行严格的高度计算是错误的，应仅将其用于决策合并方向。

2. **误区：递归溢出与栈深**：虽然路径压缩极大降低了树高，但在未调用 find 之前，若频繁执行无优化的 union，仍可能产生较深的树。在某些语言或极端大数据场景下，递归实现的 find 可能导致栈溢出。进阶思考：在生产环境中，为何通常推荐迭代式 find？

思考题：如果我们在路径压缩时同时更新子节点的秩（Rank），会对算法的时间复杂度产生什么影响？为什么标准实现中不这么做？（提示：考虑路径压缩改变树结构后，非根节点的秩是否还具有全局参考价值。）
