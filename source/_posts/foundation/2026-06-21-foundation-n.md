# 每日基础技术总结 · 2026-06-21 · 格式化字符串漏洞：%n 与栈上参数泄露

## 📚 今日主题

> **格式化字符串漏洞：%n 与栈上参数泄露**（安全基础）

### 1. 核心概念速览
格式化字符串漏洞是当用户可控字符串被直接作为printf、sprintf、fprintf等家族函数的格式参数时，格式解析器将字符串中的%转换说明当作指令执行，导致信息泄露（%p/%x）和任意内存写（%n）。其本质是可变参数机制缺乏类型与数量校验，格式串与实参的绑定完全依赖调用者提供的格式字面量，而该字面量一旦被攻击者控制，即成为任意读/写原语。该漏洞属于内存破坏类漏洞的变种，与缓冲区溢出、类型混淆同源于C语言的内存模型，是二进制安全审计、利用开发与防御的核心议题。专业工程师必须掌握，因为即使在现代应用中，将用户输入拼接入格式串的错误仍时有发生，且该漏洞常被用于绕过ASLR、篡改控制流，是理解系统安全的基础。

### 2. 底层原理剖析
在x86-64 SysV ABI中，printf的调用遵循：格式字符串地址作为第一个整数参数传入RDI，后续可变参数依次使用RSI、RDX、RCX、R8、R9，第7个及之后参数压栈。printf内部遍历格式串，遇到%说明符时，根据转换类型从对应位置取值；若格式串中指定了位置参数（如%2$s），则直接索引第n个可变参数。攻击者可以通过构造格式串中的%p/%s等从寄存器/栈中读取原本属于调用者的数据（如返回地址、canary、栈变量），实现信息泄露。%n则将截止到该位置已输出的字符数写入其参数所指向的地址，由于该参数同样从可变参数列表中获取，若攻击者能控制格式串中某个位置的参数为攻击者指定的地址，即可完成任意地址写。具体地，当格式串本身位于栈上（如局部缓冲区），攻击者可在格式串中嵌入目标地址的小端字节，然后通过计算位置偏移（如%k$n）使该地址被当作第k个可变参数取出，从而向该地址写入任意值（通过控制输出长度）。该机制完全依赖格式串的内容与可变参数布局的耦合，不存在任何边界检查。对比前端概念：前端模板引擎（如Vue的模板编译）将模板字符串静态编译为渲染函数，运行时仅执行固定逻辑，不会将用户输入作为指令解析；console.log虽接受格式占位符，但JS引擎按参数数量动态补全，且没有指针写入能力；TypeScript接口是编译期结构类型契约，与运行时内存无关。而printf的格式串是运行时指令，这正是其与前端语言/框架在类型安全与内存安全上的根本差异。

### 3. 基础代码与实战验证
```text
#include <stdio.h>
#include <string.h>

int main(int argc, char **argv) {
    int secret = 0x12345678;          // 目标变量，攻击者试图通过%n修改其值
    char buf[128];
    if (argc < 2) return 1;
    strncpy(buf, argv[1], sizeof(buf)-1);   // 将用户输入复制到栈缓冲区
    buf[sizeof(buf)-1] = 0;
    printf(buf);                     // 漏洞点：用户输入作为格式化字符串，printf将其作为指令解析
    printf("secret=%#x\n", secret);
    return 0;
}

编译：gcc -m32 -o vuln vuln.c（需32位环境；64位下需调整寄存器参数索引）。

1. 泄露：运行 ./vuln "AAAA.%p.%p.%p.%p.%p.%p.%p.%p"。观察输出，找到0x41414141（即AAAA的十六进制）对应的%p序号k（从1开始）。该k表示攻击者可控数据在printf可变参数列表中的位置。

2. 写入：构造 payload = 目标地址的小端字节 + "%" + k + "$n"。当printf解析到%k$n时，会从第k个可变参数位置取出指针，而该位置正是payload开头的地址字节，从而将已打印字符数（即地址字节长度）写入该地址。若需写入精确值，可通过填充字符控制输出长度。执行时注意shell对$的转义。
```

### 4. 常见误区与进阶思考
误区1：认为%n只能写入一个“已打印字符数”的小数值，因此难以写任意地址。实际上，通过%hn（写2字节）和%hhn（写1字节），并控制每次输出长度，可以分步写入任意宽度，实现任意内存布局。误区2：认为现代编译器（如GCC -Wformat-security）和静态分析工具能完全杜绝此类漏洞。但开发者仍可能通过自定义可变参数函数、错误使用sprintf拼接用户输入等方式绕过检查；且即使没有输出，盲打也可通过写GOT或返回地址控制执行。思考题：在x86-64下，前6个可变参数通过寄存器传递，若目标地址位于栈上且格式串也在栈上，寄存器中的栈地址能否作为%n的写目标？如何利用寄存器残留值或栈上可控数据构造任意写？该问题考验对ABI和参数索引的底层理解。
