# 每日基础技术总结 · 2026-08-28 · 进程地址空间布局：栈、堆、mmap 与 ASLR

## 📚 今日主题

> **进程地址空间布局：栈、堆、mmap 与 ASLR**（操作系统基础）

### 1. 核心概念速览
进程地址空间是操作系统为进程建立的虚拟内存布局，本质是一张由 MMU/页表/TLB 维护的虚拟页到物理页映射表。x86-64 Linux 用户态典型排列（低地址到高地址）为：ELF 程序头与 .text/.rodata、.data、.bss、堆（向上增长）、mmap 区（向下回扩，含共享库、大 malloc、文件映射）、栈（向下增长）、内核映射（用户态不可访问）。
栈由函数调用与返回驱动，是执行上下文的后进先出容器；堆是匿名内存的动态分配区域，由 brk 与 mmap 两种原语协同满足不同大小请求；mmap 是建立任意文件或匿名内存到虚拟地址空间的通用映射机制；ASLR 在 exec 时对栈顶、mmap 基址、堆基址、PIE 代码段等注入随机熵，打破固定地址复用。
它解决的核心问题：多进程物理内存隔离与复用；动态链接时符号重定位的地址空间管理；对越界/空指针等硬件异常的可检测边界；通过地址随机化提高漏洞利用难度。它在整个系统体系中的位置：位于编译链接、程序加载、物理内存分配的交汇处，是所有用户态程序内存行为的宪法，也是理解 malloc 实现、栈溢出、堆溢出、GOT/PLT 延迟绑定、JIT 内存管理、容器内存限制与内核虚拟内存调优的入口。

### 2. 底层原理剖析
底层机制如下：
1. 栈：函数调用时，CPU 的 push/call 指令将返回地址压入栈，编译器用 RSP/RBP 维护帧，局部变量通过帧内常量偏移访问；栈向低地址增长。RSP 在 x86-64 上始终保持 16 字节对齐（ABI 要求），所以 ASLR 对栈的随机化以至少 16 字节粒度进行。
2. 堆：malloc 分为两条路径。小请求通过 brk 将 program break 向高地址推，在用户态用 free list/bin 管理空闲块，复用一个连续 arena，代价是碎片与无法将部分空闲块归还 OS；大请求（glibc 默认 > 128KB）直接调 mmap 创建匿名映射，归还时 munmap 整段收回，避免长期占用堆并减少碎片。堆本身不是 C 语言概念，而是运行时/分配器的领地。
3. mmap：内核将 vm_area_struct 挂到进程 mm_struct 的红黑树，映射按页设置 PTE；访问未映射页触发缺页异常，按文件页或零页填充。共享库通过 mmap 载入，GOT/PLT 才能在运行时重定位符号。
4. ASLR：exec 加载 ELF 时，内核根据 randomize_va_space 和 personality 决定是否进行。x86-64 上 mmap 基址、栈顶、brk 基址都各自使用独立的随机采样，PIE/PIC 是 ASLR 能作用于代码段的前提：代码中只有相对偏移，加载到任意基址都能工作。
5. 与前端知识体系的对照：Java 的 interface 是运行时类型层契约，JVM 字节码中真实存在，instanceof 可以判定；TS 的 interface 是编译期结构化契约，编译后完全擦除。进程地址空间则是一个加载期/运行期的“硬连接契约”：链接器产生虚拟地址假设，MMU 页表提供映射，任一方违约（例如解引用空指针、访问未映射页）就会触发硬件异常而非类型错误。前端 JS 引擎同样分栈/堆，但栈是执行上下文与 primitive 值的保存处，堆是对象与闭包变量所在，由 GC 自动回收；而 C 中栈上可以放结构体，堆内存由显式 free 决定归还时机——这种显式所有权差异正是系统编程与托管语言的分水岭。

### 3. 基础代码与实战验证
```text
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>

int main() {
    int stack_var; // 栈变量/局部变量：地址在高位区域，ASLR 后 runs 间不同
    char *small = malloc(128); // 128B 小于阈值，由 brk 扩展堆区分配
    char *big = malloc(4 * 1024 * 1024); // 4MB 超过 MMAP_THRESHOLD，走 mmap 匿名映射
    void *manual = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0); // 手动 mmap 创建映射
    printf("stack_var=%p\n", (void*)&stack_var);
    printf("heap_small=%p\n", (void*)small);
    printf("heap_big=%p\n", (void*)big);
    printf("manual_mmap=%p\n", manual);
    free(small); // 小堆块放回用户态堆 free list，不一定还给内核
    free(big); // 大块对应 munmap，立即解除映射
    munmap(manual, 4096); // 手动解除映射
    return 0;
}

用法：gcc -o addr addr.c && ./addr，然后再次 ./addr 对照两次输出。
观察要点：stack_var 与 manual_mmap 每次 run 都会变，heap_small 也变；若用 -no-pie 重新编译，main 代码段地址固定，说明 PIE 是代码段 ASLR 的前提。
```

### 4. 常见误区与进阶思考
误区一：认为栈和堆在地址空间里是直接相邻、相向增长最终碰撞。真实布局中，栈下方（低地址一侧）有栈随机化窗口和 mmap 区域，堆上方（高地址一侧）还有载入的共享库与 mmap 分配；堆溢出突破堆后先打碎相邻堆块元数据，栈溢出通常先覆盖相邻局部变量/保存的 RBP/返回地址，二者不会“畅通无阻”地相遇。漏洞利用时需要基于堆喷/结构体伪造，不是靠两者距离近。
误区二：认为 ASLR 等于让所有字节都不可预测。ASLR 的随机单位是基址和区域布局，段内指令序、函数相对偏移、全局符号偏移都不变；mmap 返回地址页对齐（低 12 位为 0），栈 SP 也保持 16 字节对齐（低 4 位为 0）。只要泄漏一个相关地址，就能借助已知偏移构建包含 ASLR 绕过的一整套定向攻击。更关键的是，PIE/PIC 是代码段拥有 ASLR 的前提，传统非 PIE 可执行文件 .text 固定，泄漏需求也随之降低。
思考题：在开启完整 ASLR 的 x86-64 Linux 进程中，攻击者已通过漏洞泄漏了 libc 中任意一个函数的真实地址。请问：能否凭这个地址直接推导出当前线程栈上某个返回地址的位级数值？请写出推导公式中需要哪些随机量、哪些已知偏移，并说明为什么直接推导是不可行的，还需要什么信息才能让系统调用栈成为可预测的定向目标。
