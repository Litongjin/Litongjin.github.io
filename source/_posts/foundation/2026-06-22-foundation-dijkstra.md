# 每日基础技术总结 · 2026-06-22 · Dijkstra 算法的优先队列优化与负权陷阱

## 📚 今日主题

> **Dijkstra 算法的优先队列优化与负权陷阱**（算法与数据结构）

### 1. 核心概念速览
Dijkstra 算法用于求解非负权图中的单源最短路径问题。其本质是贪心 + 动态规划：维护一个已确定最短路径的顶点集合 S，每次从尚未确定最短路径的顶点中选取当前距离源点最小的顶点 u，将其加入 S，并松弛 u 的所有出边。优先队列优化版本（通常为二叉堆或斐波那契堆）将“选取最小距离顶点”这一操作从 O(V) 降低为 O(log V)，使整体复杂度从 O(V^2 + E) 变为 O((V+E) log V)（稀疏图下接近 O(E log V)）。该算法在整个计算机体系中是图论最短路问题的基石，广泛用于路由协议（如 OSPF）、地图导航、网络流建模、AI 搜索（如一致性代价搜索）等。专业工程师必须掌握它，因为最短路问题在分布式系统、负载均衡、推荐系统、知识图谱等场景中频繁抽象出现，且只有理解其贪心不变式与优先队列的交互，才能正确判断何时可用、何时会失效，避免在生产系统中产生错误结果。

### 2. 底层原理剖析
Dijkstra 算法的核心不变式：当顶点 u 从优先队列中被弹出时，u 的当前距离值即为源点到 u 的真实最短距离。证明依赖两个条件：1) 所有边权非负；2) 优先队列按距离排序弹出最小元素。因为非负权保证任何经过其他顶点的路径不会比当前弹出的距离更短，贪心选择成立。

优先队列优化的底层机制：
- 初始化：dist[source] = 0，其余顶点 dist = ∞；将 (0, source) 插入最小堆。
- 循环：弹出堆顶 (d, u)。若 d > dist[u]，说明该记录是旧记录（已被松弛过的冗余项），直接跳过（懒惰删除）。否则，遍历 u 的所有邻边 (u, v, w)，若 dist[u] + w < dist[v]，则更新 dist[v]，并将 (dist[v], v) 插入堆。
- 堆中同一顶点可能有多条记录，但每个顶点只会被真正弹出一次（第一次弹出时距离已确定），后续弹出均被跳过。总插入次数最多为 E 次，因此堆操作复杂度为 O(E log V)。

与前端概念的对比：类似于 React 的调度器（Scheduler）使用最小堆管理任务优先级，但 React 的堆按过期时间排序且可能同时存在同一任务的多个调度实例，Dijkstra 的“惰性删除”与 React 的“任务取消后跳过”异曲同工。更本质地，Dijkstra 的松弛操作类似前端状态管理中的“不可变更新”——更新 dist[v] 时插入新记录而不是修改堆内旧记录，这与 Redux 的 reducer 返回新对象而旧引用不变的模式一致，导致堆中残留旧快照，必须通过版本比对（d > dist[u]）来过滤。

负权陷阱：如果存在负权边，Dijkstra 的贪心不变式被破坏。例如源点 s 有边到 a 权重 1，s 到 b 权重 0，a 到 b 权重 -2。算法先弹出 b（dist=0），然后弹出 a（dist=1），并松弛 a->b 得到 b 的新距离 -1，但 b 已被弹出，无法重新加入已确定集合，导致结果错误。即使将 b 重新入堆，也会破坏每个顶点只确定一次的假设，使算法退化为 Bellman-Ford 的迭代形式。因此负权图必须改用 SPFA（队列优化的 Bellman-Ford）或 Bellman-Ford，或通过 Johnson 算法重赋权。

### 3. 基础代码与实战验证
```text
// 最小堆实现（简化，使用数组模拟二叉堆）
function dijkstra(graph, src) {
  const n = graph.length;
  const dist = new Array(n).fill(Infinity);
  const heap = []; // 元素为 [dist, node]
  dist[src] = 0;
  heapPush(heap, [0, src]);

  while (heap.length > 0) {
    const [d, u] = heapPop(heap);
    // 关键过滤：如果当前弹出的距离大于已记录的最短距离，说明是陈旧记录，跳过
    if (d > dist[u]) continue;

    for (const [v, w] of graph[u]) {
      const nd = d + w;
      if (nd < dist[v]) {
        dist[v] = nd;
        // 不修改堆中已有的 v 记录，而是插入新记录，堆中可能同时存在 v 的多个版本
        heapPush(heap, [nd, v]);
      }
    }
  }
  return dist;
}

// 堆操作（伪代码，实际需实现上浮/下沉）
function heapPush(heap, item) { heap.push(item); siftUp(heap, heap.length - 1); }
function heapPop(heap) { const top = heap[0]; const last = heap.pop(); if (heap.length > 0) { heap[0] = last; siftDown(heap, 0); } return top; }

// 注意：该实现假设图中所有边权非负。若存在负权边，结果不可信。

// 验证用例：
// graph = [
//   [[1, 1], [2, 4]],   // 0 -> 1(1), 0 -> 2(4)
//   [[2, 2]],           // 1 -> 2(2)
//   []                  // 2 -> 无
// ]
// 运行后 dist[2] 应为 3，而非 4，验证松弛正确。
```

### 4. 常见误区与进阶思考
误区1：认为优先队列优化改变了 Dijkstra 的正确性条件。实际上，无论使用什么堆，只要边权非负，贪心选择依然成立；堆只是加速了“取最小”操作。真正的隐患是在负权图中直接套用 Dijkstra，并依赖堆自动修正——堆能弹出新记录，但已确定集合的顶点不会重新松弛，结果仍然错误。有些开发者误以为“只要堆里有更小距离就会更新”，忽略了 Dijkstra 的每个顶点只会被正式弹出一次的前提。

误区2：忽略“跳过陈旧记录”的必要性。如果不检查 d > dist[u]，堆中残留的旧记录会导致顶点被重复弹出，虽然结果可能仍正确，但复杂度会退化为 O(E log E)，并且可能因重复松弛产生不必要的开销。更严重的是，在负权图中这种重复弹出会导致算法行为不可预测，甚至陷入类似无限循环的困境（如果负环存在）。

思考题：给定一个无向图，所有边权均为正整数，若某条边被移除后，源点到某个顶点的最短距离可能变大。现在假设你使用 Dijkstra 算法，但在优先队列中，对于距离相等的两个顶点，你总是先弹出编号较大的那个。请证明或反驳：这会导致某个顶点的最短距离计算错误？为什么？这个问题要求你深入理解 Dijkstra 的“弹出即确定”不变式，而不是停留在堆排序稳定性层面。
