进程与线程的区别（后端基础（Node.js / Java / Python））

1. 核心概念速览

进程是操作系统进行资源分配的基本单位，线程是操作系统进行CPU调度的基本单位。进程拥有独立的地址空间、文件描述符表、信号处理器等资源，线程共享所属进程的地址空间与大部分资源，仅保留独立的栈、寄存器上下文与线程局部存储。进程隔离了故障与权限边界，线程则通过共享内存实现轻量级协作。在计算机体系结构中，进程处于内核态管理之下，线程则由内核或用户态运行时调度。专业工程师必须掌握其差异，因为并发模型、性能优化、故障隔离、调试策略乃至分布式系统中的状态语义都建立在这一底层抽象之上，前端工程师理解它有助于穿透浏览器渲染进程、Web Worker、Node.js 事件循环等黑盒机制。

2. 底层原理剖析

进程与线程的本质差异在于资源所有权与调度权是否分离。操作系统内核为每个进程维护 task_struct（Linux）或 PCB，包含内存描述符 mm_struct、文件表、信号处理等；线程在内核中同样对应 task_struct，但通过 clone 时共享 mm、fs、files 等指针，仅独立维护 stack、registers、thread_info。调度器以线程为实体分配 CPU 时间片，因此多线程程序在多核上并行执行时，线程切换只需切换寄存器与栈（若在同一进程内），而进程切换必须切换虚拟地址空间（CR3/TLB 失效），成本更高。

并发与并行：进程是并发的最小单元，线程是并行的最小调度单元。进程间通信（IPC）必须通过内核提供的管道、消息队列、共享内存、Socket 等，涉及用户态/内核态切换与数据拷贝；线程间通信直接通过共享地址空间读写，但需同步原语（mutex、semaphore、futex）避免数据竞争。

与前端已有概念对比：前端『进程』类比浏览器标签页（独立渲染进程，崩溃隔离），『线程』类比标签页内的 JS 执行线程与 Worker 线程（共享同域状态）。更贴近的对比是 Node.js 的 cluster 模块（多进程）与 worker_threads（多线程）：cluster 各自独立 V8 堆，必须通过消息传递；worker_threads 共享 ArrayBuffer 内存。另一个类比：Java 接口与 TypeScript 接口的区别——Java 接口是运行时的类型约束（字节码层有 interface 结构），TS 接口是编译期的结构约束（编译后消失）。进程是内核的『Java 接口』（真实存在，由内核强制隔离），线程是 TS 接口（共享同一地址空间的逻辑边界，本质是执行流，不构成资源隔离）。

4. 常见误区与进阶思考

误区一：认为『线程比进程轻量，所以多线程一定优于多进程』。实际线程创建确实更廉价，但线程间共享内存导致隐式耦合，任何线程的野指针或越界访问都可能破坏整个进程的地址空间，造成所有线程崩溃；进程崩溃隔离性强，但 IPC 成本高。取舍取决于故障边界与通信频率，而非简单比较创建开销。

误区二：混淆『并发』与『并行』。在单核 CPU 上，多线程通过时间片轮转并发执行，但物理上不并行；多进程同样如此。并行需要多核或硬件线程。前端开发者易将 Node.js 的异步 I/O 并发理解为并行，但异步 I/O 是单线程事件循环内的并发，并非多线程并行；worker_threads 才能提供真正的并行执行。

思考题：若在 Linux 中调用 fork() 创建子进程，子进程内部再创建一个线程并修改全局变量，那么父进程能否观察到这个修改？如果不能，请从内核的 task_struct 与 mm_struct 的共享关系说明原因；如果可能，请描述需要什么条件。此题考察你是否真正理解 fork 时内存快照的语义与线程共享地址空间的边界在哪里。
