最小生成树 Kruskal 的边排序与并查集（算法与数据结构）

1. 核心概念速览

最小生成树（MST）是加权无向连通图中边权和最小的生成树。Kruskal 算法本质是贪心：将所有边按权重非递减排序，依次考察每条边，若其两个端点当前不在同一连通分量中，则选取该边，并合并两个分量。该过程通过并查集（Disjoint Set Union, DSU）高效维护动态连通性，最终形成包含 n-1 条边的树。它解决的是在保留图全部顶点连通性的前提下，最小化总边权的问题。在计算机体系内，MST 是图论中组合优化与贪心策略的典型代表，广泛应用于网络设计、聚类分析、近似算法等；在 AI 中，MST 可用于单链接层次聚类、特征选择等底层数据结构。专业工程师必须掌握它，因为它是理解贪心正确性证明、不相交集合数据结构、排序算法实际组合的基石，且能迁移至分布式系统、路由协议等真实工程场景。

2. 底层原理剖析

Kruskal 算法分两个核心阶段：

  1. 边排序：对全部 E 条边按权重升序排列，时间复杂度 O(E log E)。这是后续贪心决策的前提——只有全局有序，才能保证每次取到的当前最小边在最终最优解中。
  2. 并查集维护连通分量：初始时每个顶点自成一个集合（代表元为自身）。遍历排序后的边 (u, v, w)：
    • 若 find(u) != find(v)，说明 u、v 尚未连通，选取该边，执行 union(u, v) 将两个集合合并；
    • 若 find(u) == find(v)，说明 u、v 已连通，选取该边会形成环，必须跳过。

并查集的底层机制是树形结构：每个集合用一棵有根树表示，根节点作为代表元。find 操作沿父指针上溯至根，路径压缩将沿途节点直接指向根，使后续 find 接近 O(1)。union 操作按秩合并（将较矮树接到较高树下），保证树高不超过 O(log n)。两者结合，使得 n 次 find/union 的摊还时间复杂度为 O(α(n))，α 为反阿克曼函数，在实际中视为常数。因此 Kruskal 整体复杂度为 O(E log E)，受排序主导。

与前端概念的对比：并查集类似 TypeScript 中通过联合类型 + 类型守卫模拟的“等价类”追踪，但前端的接口偏重结构契约（编译期），并查集是运行时的动态等价关系维护。更本质地，Kruskal 的贪心选择可类比 React 的调和过程：两者都依赖全局有序/优先级策略，并利用不可变状态（并查集的集合划分）保证每一步局部最优不会破坏全局最优。但接口只描述形状，并查集描述的是状态变化与合并规则，本质是代数结构上的等价关系维护。

4. 常见误区与进阶思考

认知误区 1：认为 Kruskal 的正确性只因为“每次选最小边”。实际必须证明贪心选择的安全性——对于任意割，最小权重的跨割边一定属于某棵 MST。若忽略该证明，就无法理解为何不能简单用局部最小边替代全局最优，也无法在变体问题（如次小生成树、有向图最小树形图）中正确调整策略。
认知误区 2：忽略并查集复杂度分析的前提。路径压缩和按秩合并必须同时使用才能达到 O(α(n))；只做路径压缩不按秩合并的摊还复杂度略高但可接受，只按秩合并不路径压缩则 find 为 O(log n)，整体 O(E log n)。更危险的是忘记初始化 parent[i] = i，导致 find 死循环或越界。另外，若在遍历边时不判断 find 相等直接 union，会破坏 MST 的无环性质。
深度思考题：如果图中存在多条权值相同的边，Kruskal 算法在排序时对同权边任意排序，最终得到的 MST 边权和唯一，但边集可能不同。请从贪心选择的“割定理”出发，证明在任意排序下，Kruskal 都能选出某个最小生成树（即同权边不影响最终总权值），并说明此结论对并查集合并顺序的依赖点在哪里。
