线程切换的上下文开销：寄存器、TLS 与缓存失效（操作系统基础）

1. 核心概念速览

线程切换（context switch）的本质是内核态下对执行流的控制权转移，其开销来源于三部分：CPU 寄存器组的保存与恢复、TLS（Thread-Local Storage）指针的切换、以及高速缓存（cache）与 TLB 的失效。寄存器保存是显式的、有固定成本的；TLS 切换是隐式的，通过修改 FS/GS 段基址或专用寄存器实现；缓存失效则是间接的、高延迟的，因为新线程的地址空间（或同一进程内新线程的栈、堆访问模式）会污染 L1/L2 缓存和 TLB。该机制解决了多任务并发下 CPU 状态隔离与恢复的问题，是操作系统调度器、并发编程性能分析和异步框架设计的基础。专业工程师必须掌握它，因为任何高并发系统（如 Node.js 的线程池、Go 的 goroutine 调度、Java 的虚拟线程）的性能上限都受制于上下文切换的真实成本，而前端工程师理解的『异步无阻塞』只是绕过了线程切换，并未消除其底层代价。

2. 底层原理剖析

线程切换发生在内核态，由调度器触发。硬件层面，CPU 有一组通用寄存器（RAX/RBX/RCX/RDX/RSI/RDI/RBP/RSP/R8-R15 等）、指令指针 RIP、标志寄存器 RFLAGS、段寄存器（CS/DS/ES/FS/GS）、控制寄存器（CR3 用于页表基址）和模型特定寄存器（MSR）。切换时内核执行如下序列：

  1. 保存当前线程的通用寄存器、RIP、RFLAGS 到当前线程的内核栈或 TCB（Thread Control Block）。
  2. 保存浮点/SIMD 状态（XMM/YMM/ZMM 寄存器），通常由 XSAVE 指令按需执行。
  3. 切换 TLS：对 x86-64 Linux，FS/GS 段基址保存了 TLS 区域的线性地址，通过 WRFSBASE/WRGSBASE 或修改 MSR 实现切换；实际执行的是将新线程的 TLS 基址载入段寄存器，从而使 __thread 变量（编译器经 FS:偏移寻址）指向新线程的私有副本。
  4. 切换页表基址 CR3（若属于不同进程），或仅切换内核栈和用户栈指针（若同进程线程）。CR3 切换会导致 TLB 完全失效，因为 TLB 的 tag 是进程地址空间标识符（ASID），同进程线程共享 CR3，TLB 不失效；但不同进程切换则 TLB 清空。
  5. 恢复新线程的寄存器（包括 TLS 基址和 RIP），执行 RET 到用户态。
    缓存失效的机制：即使同进程线程切换（CR3 不变），由于新线程的栈指针、代码路径、堆访问对象不同，L1I/L1D/L2 缓存的关联集会被新线程的数据大量替换，导致旧线程下次被调度时发生 cache miss。切换频率越高，缓存失效带来的惩罚（约 100-200 个周期）占比越大。TLB 失效则涉及内存访问的页表遍历，x86-64 四级页表需多次内存访问，代价更高。
    与前端概念的对比：可将线程切换类比为 JavaScript 中『事件循环宏任务与微任务的交替』，但根本差异在于 JS 的单线程模型不涉及寄存器保存和内核调度，它的『切换』是函数调用栈的切换，成本仅为闭包和调用帧分配；而线程切换是内核态抢占式切换，成本高出几个数量级。另一个可对比的是 React 的 Fiber 架构，Fiber 节点保存了执行状态（类似 TCB），但 Fiber 切换在用户态、无需 TLS 和缓存失效。

4. 常见误区与进阶思考

误区一：认为『同进程线程切换没有缓存失效，因为地址空间相同』。实际上，即使 CR3 不变，线程切换会立即改变指令流（PC 跳转到新线程的函数）和数据访问模式，L1I 和 L1D 的局部性被破坏；新线程运行的代码区域很可能不在当前 L1I 中，导致取指停顿。频繁切换会使缓存的有效命中率大幅下降，这比寄存器保存的固定成本更致命。
误区二：将 TLS 误解为『编译期静态分配的一个全局变量』。TLS 的底层是每个线程独立的内存区域，访问必须通过段寄存器基址（FS/GS）进行相对寻址；切换线程时若不更新该基址，所有 __thread 变量都会错乱。很多工程师只看到 API 层面，忽略了内核在切换时对段寄存器的隐式修改。
思考题：在 x86-64 Linux 上，若一个进程内有 1000 个线程，其中只有 2 个线程在反复切换，其余线程处于阻塞状态。请问：频繁切换这两个线程是否会导致 TLB 失效？如果会，原因是什么；如果不会，请解释 L2 缓存失效的主要来源，并设计一个实验验证你的结论。
答案要点：不会导致 TLB 失效（同进程共享 CR3 和页表，TLB 的 ASID 相同）；但 L2 缓存失效主要来自两个线程的私有栈和不同热数据集合互相驱逐。实验可用 perf stat 测量两线程通过 sched_yield 切换时的 cache-misses，并与单线程空转的 cache-misses 对比。
