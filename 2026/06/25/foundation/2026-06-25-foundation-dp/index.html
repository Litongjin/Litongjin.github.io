状态压缩 DP 的位掩码与子集枚举（算法与数据结构）

1. 核心概念速览

状态压缩DP（位掩码DP）是一种将集合子集直接编码为整数的方法：全集大小n对应n位二进制数，第i位为1表示元素i在该子集中。其本质是用机器字长的位运算来模拟集合的并、交、差、对称差，从而将DP的状态空间从“子集对象”压缩为“整数下标”，使状态表示、转移和查表均可在O(1)或O(2^n)内完成。它解决的核心问题是：当DP状态依赖于某个集合时，如何高效枚举该集合的所有子集进行转移（即子集枚举）。机制上，位掩码利用(sub-1)&mask生成严格递减的合法子集序列，避免了对非子集整数的无效遍历。在计算机科学体系中，它是组合优化、NP-hard精确算法（如TSP、图着色、集合划分）的基石，也是理解指数级算法和状态空间压缩的必修课。专业工程师必须掌握它，因为许多真实系统（如权限控制、资源调度、特征组合）本质上就是集合上的最优化问题，而位掩码是数据编码和算法设计中最底层的表达方式之一。

2. 底层原理剖析

设全集U有n个元素，任一子集S用一个n位整数mask表示：第i位为1当且仅当i∈S。位运算直接对应集合运算：a&b为交集，a|b为并集，a^b为对称差（或剔除），~a为补集，a&-a提取最低位1，a&(a-1)清除最低位1。
子集枚举的原子操作是：对于给定mask，执行
for (sub = mask; sub > 0; sub = (sub-1) & mask) { … }
其中每次迭代的sub都是mask的一个非空子集，且序列严格递减。原理是：当sub是mask的子集时，sub-1会将sub中最低位的1变为0，并将该位右侧所有0变为1；再与mask按位与，只保留那些在mask中为1的位。由于减法的借位机制，得到的整数恰好是小于当前sub的下一个mask子集（按二进制数值降序）。该序列覆盖mask的所有非空子集，不重不漏。空集需单独处理（如sub=0或额外一次转移）。
若对所有mask枚举其子集，总迭代次数为Σ_{mask}(2^{popcount(mask)}-1) = 3^n - 2^n，因为每个元素有三种状态：不属于mask；属于mask且属于sub；属于mask但不属于sub。这就是状态压缩DP中常见的O(3^n)复杂度来源。
与前端已有知识的对比：前端通常用Set、数组或对象来表示集合，判断成员或遍历需要O(n)或更高；位掩码将集合编码为整数，可以用数组下标直接索引DP表，用位测试判断成员（O(1)），用位运算实现集合变换。这与前端中“权限标志位”或“枚举位标志”的实践一致。更本质地，位掩码与前端状态管理中的对象状态（如{a:true,b:false}）的关系，类似Java接口与TS接口的关系——两者都叫“接口”，但一个在运行时/类型系统中有完全不同的语义和实现；同样，Set/对象与位掩码都表达“集合”，但一个是高级容器，一个是底层编码，理解它们的差异是区分工程应用与算法本质的关键。状态压缩DP要求状态不可变且可哈希，位掩码天然满足，而JS对象作为状态则必须防止引用修改，这也是为什么算法中常用整数而不是对象来代表状态。

4. 常见误区与进阶思考

误区1：错误估计子集枚举的时间复杂度。许多人将for(mask in 0..2^n) for(sub in subsets(mask))视为O(4^n)，因为内层最多2^n。实际上总次数是3^n - 2^n，因为每个元素有三种独立状态（不在mask中、在mask中且属于sub、在mask中但不属于sub）。只有理解了这一点，才能正确评估状态压缩DP的可行性（例如n=20时3^n≈3.4e9，通常不可接受；n=15时3^15≈1.4e7可行）。
误区2：忽略空集的处理。标准子集枚举循环sub>0会跳过空集，但很多DP转移需要从空集开始（如dp[0]=0作为初始状态）。如果在循环内尝试用dp[mask^sub]转移，当sub=0时mask^sub=mask会造成自环，因此通常显式排除空集；但有些场景需要单独处理空集（例如子集恰好为空时状态含义不同）。忘记这一点会导致转移不完整或无限循环。
思考题：对于任意mask，(sub-1)&mask为什么能按数值严格递减的顺序遍历它的所有非空子集？请从二进制减法中‘借位’和‘置位’的角度证明其正确性。进一步，如果要枚举一个集合S的所有超集（即包含S且被全集U包含的集合），应如何设计循环？写出与(sub-1)&mask对偶的位运算公式，并解释其原理。
