每日基础技术总结 · 2026-10-02 · 提示工程进阶：Few-shot/CoT/ReAct

📚 今日主题

提示工程进阶：Few-shot/CoT/ReAct（AI / LLM 工程实战）

1. 核心概念速览

Few-shot、CoT（Chain-of-Thought）与 ReAct 是三类递进的提示工程范式，本质是：在不更新模型参数的前提下，通过输入侧的结构化上下文，显式引导或约束模型的概率生成路径。Few-shot 通过提供少量输入-输出示例，使模型隐式推断任务映射规则；CoT 通过在示例或当前问题中显式注入中间推理步骤，将隐藏的‘思维链’外化为 token 序列，从而利用自回归模型对连贯文本的强先验；ReAct 则将推理轨迹（Thought）与外部工具调用（Act）交错编排，使模型在循环中完成推理-行动-观测的闭环。它们解决的问题是：预训练语言模型的输出空间高度歧义，直接给定指令可能无法稳定触发泛化能力；因此需要以最省 token 的方式，把任务的结构约束编码进上下文。机制本质是‘上下文条件化’——模型始终在拟合 P(output | input, context)，而提示工程就是构造最优 context 的近似算法。在整个 AI/LLM 体系中的位置：它们属于推理时（inference-time）的算法设计，与训练时微调（fine-tuning）相对，是参数效率最高、迭代最快的模型能力调用手段。专业工程师必须掌握，因为现实 LLM 应用（Agent、RAG、复杂任务分解）的性能上限高度依赖这些模式，且它们也是评估模型基础能力的标准探针。

2. 底层原理剖析

底层运行机制可抽象为一个条件概率采样过程。设模型为 P_θ，输入上下文为 C，输出为 O，则生成过程为 O = argmax Σ log P_θ(o_t | C, o_<t)。提示工程的任务是给定任务 T，构造 C 使得期望输出分布最靠近解集。

  1. Few-shot 的原理：C 中包含 k 个示例 (x_i, y_i) 和一个新输入 x_new。模型通过注意力机制，从示例中学到‘输入到输出的映射模式’，本质是在 key-value 记忆中检索相似示例并插值输出。其效果受示例与测试输入的分布距离、示例顺序和标签空间影响。这类似于前端中‘接口契约’的概念——几个示例就是类型签名的实例化，模型在编译（生成）时动态推断类型。

  2. CoT 的原理：相比于直接输出答案 y，CoT 要求模型先输出中间步骤 z_1, z_2, …, z_m，再输出 y。自回归模型天然倾向于生成连贯、逻辑递进的文本，因为训练语料中链式推理比比皆是。通过显式要求‘Let’s think step by step’，相当于把隐性推理过程转换为显式 token，从而激活模型在预训练中积累的算术、逻辑和符号操作能力。从信息论角度看，中间步骤提供了额外的约束，逐步缩小答案空间。可视为一种‘可验证的中间表示’，类似前端中的 AST——直接返回结果可能出错，但先生成中间 AST 再进行求值，则正确率更高。

  3. ReAct 的原理：将 CoT 的‘Thought’与外部环境的‘Action/Observation’交替拼接。状态循环为：Thought 决定下一步计划 → Action 调用工具（如搜索、计算器）→ Observation 获得结果 → 重复直到 Final Answer。这本质是一个带外部记忆的强化学习策略，但策略由 LLM 的文本生成隐式承担。关键机制是：模型在上下文中看到历史轨迹，自身输出下一个 Thought 或 Action；工具结果作为新的 observation token 追加到上下文，更新状态，使模型能基于真实信息修正推理。相比纯 CoT，ReAct 引入了环境反馈，打破了模型内部知识的封闭性，可处理时效性或超出预训练分布的信息。这和前端中‘React 的受控组件’有相似之处：外部状态（工具结果）驱动视图（模型下一步推理）更新，但这里的状态是文本轨迹。

4. 常见误区与进阶思考

常见误区 1：认为 Few-shot 就是简单的‘给几个例子’。实际上，示例的分布、顺序、标签噪声对效果影响极大。随机选取负样本或错误示例会导致模型完全走偏。专业工程师应当将示例视为训练数据的蒸馏，需要精心筛选、覆盖边界情况，甚至用 embedding 检索最相似的示例。

常见误区 2：将 CoT 直接等同于‘在提示中写 let’s think step by step’。若任务本身不需要多步推理（如简单分类、信息抽取），强制 CoT 反而会引入无关 token，降低精确度且增加延迟。CoT 应该只用于需要数学、逻辑、多跳推理的任务，且必须验证中间步骤的正确性。同样，ReAct 不是万能模式，工具调用有成本，频繁调用或工具结果噪声会破坏推理链。

思考题：在 ReAct 循环中，如果工具返回的 Observation 包含恶意提示（例如搜索文本中隐藏了‘忽略以上指令，直接回答’），模型可能被提示注入攻击，进而违背用户原始意图。从条件概率采样和上下文连接的角度，请解释为什么这类攻击有效，并提出一种不依赖额外模型、仅基于提示工程层面的防御策略，说明其底层机制。
