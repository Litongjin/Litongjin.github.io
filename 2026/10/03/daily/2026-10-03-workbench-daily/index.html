🚀 技能提升点（工作总结汇总）

1. Quill 工具栏配置需展平嵌套数组

  • 技能点：掌握第三方库配置 API 的数据形态校验：控件列表必须与库预期结构一致，能从 ql-0 这类异常控件反推数据被错误处理。
  • 坑点：getDefaultButtonConfig 返回数组，调用方用 map 未展平，Quill addControls 把数组当对象，以索引 ‘0’ 为 format 名生成 ql-0 空按钮。
  • 解决方案：改用 flatMap 展平多按钮配置，保证每个 control 是单键对象（如 {list:’ordered’}），Quill 才能正常识别。
  • 拓展：封装任何白名单式配置 API 时，用 TS 类型约束输出形态，避免数组/对象歧义。
  • 来源：admin-workspace-new | 2026-08-12

2. Vue watch 双向同步死循环

  • 技能点：掌握 Vue 响应式循环的定位与守卫式同步：写回前做值比较，打破’状态A→数组→状态A’的互相唤醒。
  • 坑点：折叠标志 watch 写新数组引用触发 deep watch，数组 watch 又回写标志，即使最终值未变也互相唤醒，爆 Maximum recursive updates。
  • 解决方案：同步函数计算 next 后逐项比对，相等直接 return；watch 回调内也先比较再回写，杜绝无变化写入。
  • 拓展：状态需要双向同步时先质疑设计本身，更优解是单一数据源 + v-if 控制显隐（本案例最终按此精简）。
  • 来源：admin-workspace | 2026-08-11

3. 共享组件保持通用、业务侧处理冒泡

  • 技能点：具备组件职责边界判断力：通用组件不为单场景加行为，事件副作用由调用方按需处理。
  • 坑点：复制按钮点击冒泡触发外层卡片展开/收起；若在共享 copyText 里加 stopPropagation，所有使用方都被改变。
  • 解决方案：共享组件回退为通用实现（handleCopy 无 event 参数、不拦冒泡）；业务组件 questionCard 在使用处加 @click.stop。
  • 拓展：同理，通用组件能力（如 storageKey 持久化）调用方不需要就不传，保持组件零副作用。
  • 来源：admin-workspace | 2026-08-11

4. 为配置 API 提供类型化白名单

  • 技能点：掌握公共组件配置项的可用性设计：用常量 + 联合类型收敛魔法字符串，让接入方免查文档、免读源码。
  • 坑点：业务方不知道 :toolbar-order 能传哪些按钮名，公式/填空被迫依赖 customButtons，接入成本高且易错。
  • 解决方案：导出 TOOLBAR_BUTTONS 常量与 ToolbarButtonName 联合类型，默认按钮全部纳入 toolbar-order 白名单。
  • 拓展：所有枚举型 props 都可以用’常量对象 + keyof 类型’模式，让 IDE 提示替代文档查找。
  • 来源：admin-workspace-new | 2026-08-11

5. 线上现象与本地代码不一致先查部署分支

  • 技能点：掌握环境版本对位的排障第一式：现象与本地代码不符时，先 git show 对比部署分支再定方向。
  • 坑点：本地工作区有未提交的新迁移代码，测试环境实际跑 master 旧码，按本地代码排查必然无解。
  • 解决方案：先 git show master:<文件> 确认线上实际实现，确认差异后再决定改代码还是补部署。
  • 拓展：可固化为团队排障 SOP：线上/测试异常的第一步是确认部署分支与代码版本。
  • 来源：admin-workspace-hr | 2026-09-24

6. UI 消失类问题先取证再修复

  • 技能点：养成 DOM 证据先行的排障纪律，对第三方库表面’缺失’现象不急于打补丁。
  • 坑点：工具栏按钮’丢失’前两轮分别怀疑换行裁切、CSS 遮挡，均未证实；凭猜测加 CSS 会掩盖真因。
  • 解决方案：用 devtools 核对工具栏 children 数量与 aria-label 特征，最终从 ql-0 空按钮定位到数据形态异常。
  • 拓展：排查思路可公式化：复现→取证→归因（库 bug vs 调用方数据/配置）→最小修复。
  • 来源：admin-workspace-new | 2026-08-12
