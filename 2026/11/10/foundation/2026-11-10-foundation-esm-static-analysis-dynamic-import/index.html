JavaScript Module System：ESM 的静态分析与动态导入（Import()）执行流（前端底层与计算机基础）

1. 核心概念速览

ESM 是 ECMAScript 语言级的模块系统（规范 §16.2 Modules），本质是一套「解析期静态确定的模块图 + Link/Evaluate 两阶段执行模型」。

它解决的问题：在语言层给出可静态分析的依赖与导出集合，使 Host（浏览器 / Node / 打包器）能在不求值任何模块代码的前提下完成依赖解析、绑定建立与图完整性校验。

机制要点：

  1. Parse 阶段（ParseModule）从 AST 中抽出 ImportDeclaration / ExportDeclaration，产出模块记录的四张静态表：[[ImportEntries]]、[[LocalExportEntries]]、[[IndirectExportEntries]]、[[StarExportEntries]]，以及 [[RequestedModules]]。这一步不执行任何代码，所以 specifier 必须是 StringLiteral，import 必须位于顶层。
  2. Link 阶段（Instantiate）按 DFS 递归解析 specifier（HostResolveImportedModule），为每个模块创建 Module Environment Record，把所有 import 绑定建成指向目标模块 binding 的间接绑定——此时只建立引用关系，不读取值。
  3. Evaluate 阶段按 DFS 后序执行模块体（[[ECMAScriptCode]]）。

与 import() 的分界：静态 import 的 resolve / link / evaluate 全部在宿主加载模块图时一次性、深度优先地完成；import() 是一个运行期求值的 CallExpression，把「解析 specifier、加载、link、evaluate」推迟到调用点，通过宿主钩子 HostImportModuleDynamically 异步完成并返回 Promise。二者共享同一 Realm 的 Module Map，因而命名空间对象与副作用执行次数仍是一次。
