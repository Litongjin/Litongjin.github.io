动态规划：背包问题与状态转移（算法与数据结构（面试））

1. 核心概念速览

动态规划（Dynamic Programming, DP）是一种将复杂问题分解为重叠子问题（Overlapping Subproblems）并存储子问题解以避免重复计算的最优化算法范式。背包问题是其典型应用，本质是在有限资源约束下寻求目标函数的极值。它位于算法理论核心，是贪心算法的反例补充及分治法的优化升华。对于工程师，掌握 DP 意味着理解‘空间换时间’的代价交换机制，以及如何在状态空间中通过递推关系精确建模最优子结构（Optimal Substructure）。在 AI/ML 中，DP 是隐马尔可夫模型、路径规划等底层逻辑的基础。

2. 底层原理剖析

DP 的核心在于两个要素：1. 状态定义：用维度数组表示当前决策阶段的特征；2. 状态转移方程：描述从上一阶段状态推导当前状态的数学逻辑。

底层机制对比：前端工程中的记忆化搜索（Memoization）或 Redux/Pinia 的状态树更新，本质是‘有缓存的状态流转’，但 DP 强调无后效性——即当前状态仅依赖于前驱状态，不依赖历史路径的具体组合。这与 TS 接口定义‘类型契约’不同，DP 定义的是‘计算契约’。

以 0-1 背包为例：

  • 状态 dp[i][w] 表示前 i 个物品放入容量为 w 的背包的最大价值。
  • 转移方程：dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])
  • 物理意义：第 i 件物品要么不选（继承 i-1 时的最大值），要么选（剩余容量容纳的价值+当前物品价值）。
  • 空间优化：利用一维数组滚动更新，因 dp[i] 仅依赖 dp[i-1]，需逆序遍历容量以覆盖旧值而非读取新值。

4. 常见误区与进阶思考

  1. 正序 vs 逆序混淆：在完全背包（物品可无限次选取）中通常正序遍历，而在 0-1 背包中必须逆序。错误顺序会导致逻辑上对同一物品的重复叠加，破坏状态定义的独立性。
  2. 初始状态定义错误：若未正确初始化 base case（如重量为0时价值为0），后续所有转移均基于错误基准，导致全局最优解失效。
